System Overview
The project is divided into two phases: software simulation (using Verilator and SDL) and physical hardware deployment (FPGA). The entire system operates on a single 25.175 MHz master clock.

Module 1: Clock Generation Unit
This unit distributes the 25.175 MHz master clock to all system components. For modules requiring a 60 Hz update rate (like game logic), this unit generates a single-cycle enable pulse using a mod-n counter. The counter increments every clock cycle and resets at n-1, outputting a pulse. The value of n is calculated as (25,175,000 / 60) to achieve exactly 60 Hz.

Module 2: Input Processing Pipeline
This module conditions raw, asynchronous physical button presses into safe, synchronous 1-cycle pulses for the system.
Synchronizer: The raw input passes through two flip-flops in series to resolve metastability and align the signal with the master clock.
Debouncer: A mod-m counter ensures the signal is held high continuously for at least 20 ms. If the input drops to 0 at any point, the counter immediately resets to 0.
Edge Detector: Converts the sustained high signal from the debouncer into a single-cycle pulse so that one physical button press registers exactly once in the game logic.

Module 3: Random Piece Generator
This module generates pseudo-random pieces using a 3-bit Linear Feedback Shift Register (LFSR). It is initialized with a non-zero seed (e.g 001). Because a 3-bit LFSR cycles through exactly 7 non-zero states, it maps perfectly to the 7 Tetris piece types. It runs continuously on the 25.175 MHz clock. Since human input timing is unpredictable, the LFSR state at the exact moment a piece is requested provides reliable randomness.

Module 4: Piece Buffer Management
This module manages the piece pipeline. It contains 3-bit registers for the Active (falling) piece, the Next piece, and the Hold piece. It also maintains a 'hold empty' flag and a 'hold lock' flag. An internal FSM takes care these buffers, executing piece swaps when requested and enforcing the rule that a player can only swap with the hold buffer once per piece drop.

Module 5: Playfield Memory 
This module stores the locked blocks on the board. It consists of a 10x20 grid of flip-flops (200 bits total), representing whether a specific block in the playfield is occupied or empty. It allows the game state logic to perform parallel collision checks and provides the VGA controller with the data needed to render locked blocks.

Module 6: Game State and Control Logic
This module tracks the live geometry of the active falling piece (coordinates and rotation state). It takes inputs from the Input Module (user commands), the Playfield Memory (for obstacle detection), and the 60 Hz enable pulse (for gravity). It is responsible for calculating tentative moves, checking for collisions, updating the piece's coordinates, and locking the piece into memory when it hits the floor. It outputs the active piece coordinates to the VGA controller and sends a spawn pulse to the Piece Buffer when a new piece is needed.

Module 7: VGA Controller
This module handles the display output. It runs continuously on the 25.175 MHz clock to maintain internal horizontal and vertical pixel counters, which are used to generate the necessary HSYNC and VSYNC signals for the monitor. It translates the current pixel counters into Tetris grid coordinates (row and column). It then reads the Playfield Memory and checks the active piece coordinates from the Game State module. If a locked block or the active piece exists at the current coordinate, it outputs the white to the screen, otherwise, it outputs black.

CODE DESCRIPTION:

Module 6:
1. Internal Inputs and Control Signals

Apart from the main inputs and outputs of the module, several internal signals are used to control the game.

State – stores the current state of the FSM and determines which operation the game should perform.
Cell Index – selects one of the four cells of the active piece when the piece is being locked into the playfield.
Tick Count – counts the 60 Hz clock ticks used to control the falling speed of the piece.
Lock Delay Count – counts the time for which a piece remains on the ground before it is permanently locked.
Fall Due – indicates when the next gravity movement should occur.
Gravity Y – represents the position one cell below the current piece and is used for gravity collision checking.
Tentative Left/Right Position – represents the possible position of the piece after moving one cell left or right.
Tentative Rotation – represents the next rotation state of the piece.
SRS Tentative X and Y – store the position obtained after applying the Super Rotation System during rotation.
Final Drop Y – stores the lowest valid position reached during a hard drop.
Write Address and Write Data – are used to write the locked piece cells into the playfield memory.

The gravity and lock-delay timing are controlled using predefined tick counts.

2. Shape Lookup Table

The shape lookup table determines the coordinates of the four cells of the active Tetris piece.
It takes active X, active Y, active piece ID, and rotation state as inputs. Based on these values, it provides the coordinates of all four cells of the piece.
The lookup table contains the required arrangements for all seven Tetris pieces and their different rotation states. Therefore, whenever the position or rotation of a piece changes, the lookup table provides the corresponding coordinates of its four cells.

3. Collision Checking

Collision checking uses active X, active Y, active piece ID, and rotation state to determine the coordinates of the four cells using the lookup table.
These coordinates are then checked against the playfield memory.
The system checks whether any cell:
  i. goes outside the playfield.
  ii. overlaps with an already occupied cell.

If either condition occurs, a collision is detected.
This collision-checking logic is reused for movement, gravity, rotation, spawning, and hard-drop operations.

4. Super Rotation System (SRS)

The rotation logic follows the Super Rotation System (SRS) guidelines used in Tetris.

When a piece is rotated, the system first considers the normal rotated position. If that position causes a collision, it tries the predefined SRS kick positions.
Five possible kick positions are implemented. These allow the piece to adjust its position when rotation causes a collision with a side wall, floor, or other boundary of the playfield.
Separate kick values are used for the I-piece and the other Tetris pieces, according to the SRS rules. Each possible position is checked for collision, and the first valid position is selected.

5. FSM States

The overall game operation is controlled using a finite-state machine with the following states:

i. MOVE
This is the normal gameplay state. The player can move the piece left or right, rotate it, or perform a hard drop. The piece also automatically moves downward according to the gravity timing.

ii. LOCK_DELAY
When the piece reaches the floor or another block, it enters the lock-delay state. A short delay is provided during which the player can still move or rotate the piece. A successful movement or rotation resets the lock-delay timer. If the timer expires, the piece is locked.

iii. LOCK
In this state, the four cells of the active piece are written into the playfield memory. After all four cells are written, the FSM moves to the spawn state.

iv. SPAWN
The next piece is placed at the default starting position with its initial rotation. The required counters are also reset, and a spawn pulse is generated.

v. SPAWN_WAIT
This is an intermediate state between spawning the piece and checking its starting position.

vi. SPAWN_CHECK
The newly spawned piece is checked for collision. If it overlaps with an occupied cell, the game enters the GAME_OVER state. Otherwise, it proceeds to the MOVE state.

vii. GAME_OVER
The game remains in this state once no valid position is available for spawning a new piece.
